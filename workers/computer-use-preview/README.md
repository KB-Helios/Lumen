# Lumen Computer Use sidecar

This is the fixed local executor for Lumen's Computer Use protocol. Rust owns model calls, provider keys, action planning, approvals and foreground recovery. The worker receives only validated `begin`, `observe`, `act` and `end` JSON lines through inherited stdin/stdout. It reads no provider credentials and exposes no generic SDK operation or script execution.

The binding wire contract is `docs/architecture/computer-use-protocol.md`. Runtime dependencies are Python 3.11, Playwright 1.62.0 and Cua Driver 0.34.0. `requirements.lock` fully pins the build environment, including the Windows x64 Cua wheel SHA-256. `NOTICE.md` records provenance and the third-party MIT license.

Browser execution launches installed Microsoft Edge with a fresh Playwright context. Requests and navigation are HTTP(S) only, without embedded credentials. DOM references retain their actual frame and node; each new observation invalidates prior references. Semantic value changes and unique option selection require independent value read-back and matching post-observation. Visual typing resolves the focused editable node from the current snapshot, retains its frame and selection, and refuses protected or unobserved controls. Semantic actions omit screenshots. Coordinates require the current requested screenshot. A successful click or gesture is never automatic confirmation.

Native execution uses a private Cua worker with immutable bounded authorization, no full desktop display permission and one executable ceiling. Every operation also verifies the exact PID, HWND, executable, process creation identity and manifest hash. Native setValue can confirm a unique semantic value read-back. Native invoke and click refuse before SDK dispatch because acceptance testing detected a change in window order. Invoke remains advertised for Rust's explicit one-time foreground approval in Fast mode. Native selection, keypress, type, scroll, move, drag, double click, right click and navigation also return an explicit background refusal. Keyboard routes refuse before SDK dispatch because focus preservation has not been established on modern Notepad. Native scroll is refused because the adapter cannot bind the SDK's client coordinates to a capture or prove control-specific pixel behavior. Background mode never escalates a refusal; foreground recovery belongs to Rust and requires approval. Scroll on the wire is 1–3,000 pixels; browser semantic scrolling remains available.

The pinned Windows SDK always reports `elements_complete=false`, including successful positive UIA snapshots: it cannot prove negative existence. This is separate from actual `degraded` and `truncated` flags, which block input. Screenshot actions retain the actual native capture ID; the SDK's typed window-state output omits it, so this adapter reads the fixed tool's structured metadata internally. Cold UIA capture can exceed its bounded five-second deadline; that runtime then refuses further input and requires a new begin. No input is replayed after uncertainty. Duplicate command IDs return the cached outcome or refusal, including failures reserved before input.

Typed UIA receipts can contain the SDK's `UNKNOWN` or `NOT_APPLICABLE` delivery enum. These make no input-delivery claim; a value change still needs independent post-observation. Explicit SDK refusals, errors, escalation, foreground delivery and malformed metadata remain nonretryable uncertainty, including when the immediate value read-back matches. Only a local refusal before SDK dispatch can permit Rust to request foreground approval. A verified browser value change that changes the observed URL also ends the batch for replanning.

From the repository root, stage with `bun scripts/stage-computer-use.ts`. PyInstaller uses onedir layout: the fixed executable and `computer-use-runtime/` must be packaged beside each other. The runtime contains the SDK DLL, `cua-driver.exe`, `cua-driver-uia.exe`, Playwright and Python resources. All native files have hashes pinned from the verified published wheel. The generated `.build/staged-runtime-inventory.json` records every executable/runtime resource hash; cached staging verifies it and rebuilds or refuses modified, missing or unexpected files. Source and packaged `--health` probes are bounded and must agree. Readiness is true when either actual route is usable.

Run local checks from this directory:

```powershell
rtk proxy .venv/Scripts/python.exe -m unittest discover -v
rtk proxy .venv/Scripts/python.exe benchmark_executor.py --native --baseline
rtk proxy .venv/Scripts/python.exe benchmark_executor.py --packaged --native
```

Tests use a disposable HTTP fixture in actual headless Edge and a disposable native Win32 window. The benchmark excludes a warm-up, measures 20 warm repetitions of five distinct fields, and records command latency, payload sizes, screenshot count and verified outcomes in `.build/benchmark-source.json` and `.build/benchmark-packaged.json`. `--baseline` measures the reproduced original local screenshot sequence with duplicate load waits and 500 ms sleep per input; it excludes extra upstream modifier screenshots. It performs no cloud tasks. These are executor measurements; they do not measure provider latency, token usage or end-to-end Rust batching. A potential one five-action plan versus five old single-step turns is deterministic planner behavior, not measured provider savings.

The unused files under `upstream/` retain Google's Apache-2.0 provenance from https://github.com/google-gemini/computer-use-preview at `77c9797e943aad63bbc963b7fd092a9e51c07863`. They are retained for provenance and are neither imported nor packaged by the fixed executor.

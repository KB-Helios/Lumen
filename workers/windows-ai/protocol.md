# Lumen Windows AI bridge protocol v1

The authoritative frontend shapes are `src/services/windows-ai/windows-ai.types.ts` and service methods are in `windows-ai-service.ts`. The helper accepts UTF-8 JSON lines `{id: string, operation: string, payload: object}`. Rust is the only caller. IDs match `[A-Za-z0-9._:-]{1,80}`. Input lines are limited to 6 MiB (base64 encoded images included); decoded image bytes to 4 MiB; text to 64 KiB UTF-8. Output lines are limited to 1 MiB and total response text to 256 KiB. Never output prompts, file paths, secrets, raw exception/log content, or arbitrary SDK objects.

Output envelopes all carry `id`: `{id,type:"result",data:object}`, `{id,type:"delta",text:string}`, `{id,type:"progress",phase:string,progress:number|null}`, or `{id,type:"error",code:string,message:string}`. One terminal result/error ends an operation. Progress/delta are optional. Native cancellation accepts `{id:"cancel-control",operation:"cancel",payload:{requestId:"active-id"}}`, cancels the target's WinRT/.NET operation, and returns a bounded cancellation result; Rust may kill a non-responsive helper/job as fallback. No output message may masquerade as readiness or completed inference.

Operations and native-only payloads:

- `status`: `{preferences: WindowsAiPreferences, accessToken?:string}`. Return `{version:1,host,features,preferences,agents,appIndex,accessTokenConfigured}` matching the snapshot schema. Status is passive and cannot create a model/index or download anything. Native feature IDs are languageModel/aion/summarize/rewrite/ocr/imageDescription/appContentSearch/agentDiscovery/agentInvocation/agentRegistration. Rust may add native-authoritative preferences and token-configured state to the helper's result.
- `prepare`: `{featureId,preferences,accessToken?:string}`. Enforce explicit download consent upstream and in the helper; feature readiness and result statuses remain checked. Return a snapshot or operation result followed by Rust status refresh. Actual percentage is 0..1, otherwise null.
- `text`: `{requestId,engine:"windows"|"aion",task:"answer"|"summarize"|"rewrite"|"write",text,preferences,accessToken?:string}`. Native Rust may replace an answer's text with its bounded retrieval prompt. Return `{text,engine,model,citations:[]}`; Rust inserts only its verified local file citations. Append emitted token deltas, then check the terminal SDK result.
- `image`: `{requestId,operation:"ocr"|"describe",imageBase64,preferences,accessToken?:string}`. Rust resolves the file ID and reads confined bytes before calling the helper. Return the text-result shape with engine windows.
- `indexSync`: `{version:1,items:catalogue.items,preferences}`. Catalogue is embedded/trusted public Lumen content from `src/services/windows-ai/catalogue.json`, never frontend-supplied personal data. Return `{ok,message}`.
- `indexSearch`: `{query,limit:20,preferences}`. Return an array of `{id,source:"semantic"}` or other matched stable catalogue IDs; Rust resolves titles/descriptions/destinations against its embedded catalogue and rejects unknown IDs.
- `indexDelete`: `{preferences}`. Delete only Lumen's fixed named Windows public-content index; return `{ok,message}`.
- `agents`: `{preferences,verifyOwnRegistration?:true}`. Explicit discovery returns WindowsAgent[] from a Windows-owned ODR executable location, with capped metadata. Native-only removal verification requires Lumen identity and returns at most its own fixed name/action/package tuple, without caching other agents; it remains available after opt-out. Absence of ODR produces a typed unavailable reason. Discovery is separate from a passive status check.
- `invokeAgent`: `{agent:WindowsAgent,prompt,preferences}`. Agent came from Rust's most recent discovery cache; the helper independently rediscovers the exact installed tuple even when its process is new. Find the exact packageFamilyName/actionId in Windows AI Actions and invoke with agentName/prompt text entities. Prompt limit is 4,000 characters; no attachments or arbitrary launch URI.
- `registerAgent` / `unregisterAgent`: `{preferences,agentDefinitionPath}`. The definition is Lumen's fixed packaged asset, never chosen by React. Require current package identity, operate only on the Lumen agent, and re-query to verify. Return `{ok,message}`.
- `shutdown`: `{}`. Dispose model/index sessions and exit.

Tauri command names consumed by the native service: `windows_ai_status`, `windows_ai_update_preferences` (`patch`), `windows_ai_prepare` (`featureId`, `requestId`, `onEvent`), `windows_ai_text` (`request`, `onEvent`), `windows_ai_image` (`request`, `onEvent`), `windows_ai_search_content` (`query`), `windows_ai_rebuild_content`, `windows_ai_delete_content`, `windows_ai_discover_agents`, `windows_ai_invoke_agent` (`agentId`, `prompt`), `windows_ai_set_registration` (`enabled`), `windows_ai_set_access_token` (`token`), `windows_ai_cancel` (`requestId`), `windows_ai_consume_activation`. Preparation/text/image Channels use the frontend WindowsAiEvent schema with requestId; Rust translates helper envelopes. Snapshot updates use `lumen://windows-ai-status`; pending activation wakeups use `lumen://windows-agent-activation` and are consumed once after hydration.

Native preferences default to the defaults declared in the TypeScript schema; all privileged booleans default false. Rust persists/rechecks them before every operation. Framework/runtime/signing requirements never become ready based on preferences alone. Registered agent identity is `lumen.browser`, action ID `LumenBrowserAgent`, and valid entry URI is `lumen:agent?agentName=lumen.browser&prompt=<encoded text>`. Package identity name/publisher are coordinated by the native packaging task; the helper must have its own matching application identity.

Helper build output is `src-tauri/binaries/windows-ai/lumen-windows-ai.exe` with adjacent dependencies. Tauri bundles that directory as `windows-ai/`. Rust uses the packaged path or this fixed development path. It never searches PATH for an arbitrary helper. Aion NuGet 1.0.0 and ARM64 framework MSIX release v1.0.0.0 use the official release-provided SHA-256 digests; SDK checksum `208e739716ba35e87c8a7b0c10013fee63080c8cfb383793a706d0a5a73e7a7f`. Model download is a separately consented optional setup step, never part of normal status or the x64 build.

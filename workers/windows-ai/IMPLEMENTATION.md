# Stable Windows helper implementation

The helper compiles against exactly Windows App SDK `2.5.1`. Runtime binding uses the restored Runtime package's release constant `0x00020005`, empty version tag, minimum version `0x0002000500010000` (2.5.1.0), and family `Microsoft.WindowsAppRuntime.2_8wekyb3d8bbwe`. A packaged helper checks its actual dependency graph; an identity no-op does not establish runtime readiness. There is no older or experimental fallback.

This hidden, fixed-resource helper runs under Rust's kill-on-close Job Object. JSON-line operations are bounded and serialized; Rust retains credential ownership, early cancellation IDs and authoritative preference checks. Language generation, summarization, rewriting, writing, OCR and image description use the pinned Microsoft projections. Passive status checks readiness without downloading models or installing providers. Model preparation requires the relevant feature permission and download consent; ordinary requests require ready models. Images come from Rust's confined reads with a decoded-image dimension and pixel cap.

Native Aion is `unavailable/aion_no_stable_contract` on every architecture. Its adapter, ARM64 package and sample-derived binding are absent. Experimental speech and language-model metadata are not compiled or shipped.

Stable App Content Search remains `accessRequired/app_content_access_not_provisioned` after independent identity and runtime checks. Its Microsoft-issued feature-specific activation contract and owner grant are unverified. The native language token is never reused for search. Index opening, querying, preparation, enumeration, synchronization and deletion stop before any search SDK operation; passive status does not probe the search SDK without access. Existing indexes cannot be maintained until the separate grant is implemented and validated. The fixed `Lumen.PublicHelp.v1` catalogue contains only shipped public help/action items; personal file contents remain in Lumen's confined SQLite index.

Agent discovery uses a bounded Windows-owned ODR executable and revalidates the exact package/action tuple before Windows App Actions invocation. Incoming protocol activations create bounded drafts and never start Computer Use. The optional sparse identity declares matching main/helper identities, `systemAIModels`, and the stable framework dependency.

`bun run stage:windows-ai` restores locked dependencies, publishes to a fresh owned directory with isolated MSBuild artifacts, checks the real package graph, runs core and matching-architecture protocol checks, then replaces the staged directory. Ancestor directories are validated without traversing retained build siblings; trees copied, replaced or removed receive bounded recursive containment and reparse checks. Earlier build/cache inputs remain preserved. `bun scripts/stage-windows-ai.ts --arch=arm64 --build-only` verifies ARM64 compilation and package contents without replacing the x64 stage.

The recorded x64 stage passed 2 package, 11 core and 9 native protocol checks. ARM64 passed build/package and 11 core checks on an x64 host; ARM64 execution and hardware readiness remain unverified. An unsigned sparse identity package was built, but it was not signed or registered. Eligible hardware, ready models, the owner language token, the search activation contract and grant, real inference/search, and packaged acceptance remain pending. Staging installs no model, execution provider, identity package or certificate.

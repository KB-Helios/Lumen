# Windows AI bridge

This helper implements the approved Windows integrations behind Lumen's typed service boundary. It is a hidden, fixed-resource process owned by Rust's kill-on-close Job Object. JSON-line operations are bounded and serialized; cancellation reaches queued and active requests. Rust retains early cancellation IDs, rechecks authoritative preferences before dispatch, and kills a helper that does not finish cancellation within two seconds.

The pinned Microsoft projections provide language generation, summarization, rewriting, writing, OCR and image descriptions. Passive status checks use actual readiness and execution-provider results. Only the explicit Prepare operation can call model preparation, and it requires the relevant feature permission plus download consent. Ordinary requests require ready models. Phi Silica access uses the configured native credential token. Images come from Rust's confined file reads, with an additional decoded-image dimension/pixel cap. Results never claim success without checking the SDK terminal status.

Aion is compiled against the official checksum-verified ARM64 SDK, using its process-scoped framework dependency and text-session APIs. Runtime use requires the separately installed Microsoft-signed framework and certified, ready QNN provider. It has no x64 or CPU fallback. With the default `keepWarm: false`, a fresh helper can load an already installed Aion model on an explicit request; no ephemeral preparation cache is required. It releases its model after the request and on shutdown.

App Content Search uses the single fixed index `Lumen.PublicHelp.v1`. Its ten public help/action items are embedded in the helper and Rust; arbitrary caller content is rejected. Preparation waits for actual semantic and lexical capability initialization, with real progress and cancellation. Rebuild replaces only these public items and checks indexing statistics. Passive status reads statistics from an already existing, ready index, so closing a helper does not erase the reported persistent index state. Personal file contents remain in Lumen's confined SQLite index. Increment the index/catalogue version when changing this immutable shipped catalogue; explicit Rebuild repairs or replaces its content. Query IDs are resolved against the trusted current catalogue before navigation.

Agent discovery uses a bounded Windows-owned ODR executable, never PATH or a caller-selected process. Invocation checks both Rust's discovered tuple and a new helper-side discovery before resolving the exact package/action in Windows App Actions. Its terminal invocation result must succeed. Registration operates on the fixed Lumen asset and is verified by a separate catalogue read. Removal verification returns only Lumen's own tuple and stays usable after agent consent is revoked. Incoming protocol activations create bounded drafts, with short duplicate-delivery suppression; they never start Computer Use.

The optional sparse package declares matching main/helper identities, `systemAIModels`, and the exact preview framework dependency. Packaged readiness checks the actual dependency graph; an `OnPackageIdentity_NOOP` bootstrap result is not treated as readiness. Unpackaged probing can enumerate a stable installed runtime without misreporting experimental AI availability.

`bun run stage:windows-ai` restores architecture-specific locked dependencies, publishes the self-contained .NET runtime, runs the nine core checks and eight native protocol checks, then stages the verified fixed layout. `bun scripts/stage-windows-ai.ts --arch=arm64 --build-only` verifies compilation against the ARM64 Aion projection without replacing the current x64 staged helper. Neither command installs models, execution providers, identity packages, certificates, or browser experiment flags.

Both x64 and ARM64 publication passed on 2026-10-04. ARM64 execution requires its target hardware and was not exercised here.

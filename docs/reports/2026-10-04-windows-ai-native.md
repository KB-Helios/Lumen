# Windows AI native verification

Verified locally on 2026-10-04 in the approved Windows preview scope. These results establish native compilation, boundary regressions and passive host probing; they do not establish live inference on unsupported hardware or an unconfigured runtime.

- Published the pinned .NET helper for `win-x64` and `win-arm64`, with warnings treated as errors. The ARM64 build consumes the checksum-verified official Aion SDK. Nine core checks passed in both build lanes; eight executable protocol checks passed on x64.
- Rust formatting and clippy (`--all-targets --all-features -- -D warnings`) passed with normal configured resources. `cargo test --all-features` passed 99 tests with four explicitly ignored hardware/sidecar checks. The ignored real Windows AI helper status test was then run separately and passed through Rust's actual Job Object supervisor.
- The final full Tauri release/NSIS build passed. Its installed isolated smoke passed exact vector search, lexical fallback, native window show/hide, sanitized diagnostics, uninstall and profile cleanup. Current installer hash and results are retained in [packaged evidence](../../artifacts/packaged/packaged-smoke.json).
- Built the optional unsigned sparse MSIX with Windows SDK MakeAppx 10.0.28000.1839 using the documented external-location `/nv` option. Its fixed main/helper identities, action definitions, preview framework dependency and `systemAIModels` declaration are included. It was not signed, trusted or registered on this machine.
- The current x64 host reported Windows build `10.0.26300.0`, no Lumen package identity, stable `Microsoft.WindowsAppRuntime.2 2.5.1.0`, and `VitisAIExecutionProvider (Certified, NotReady)`. Provider readiness can change and is refreshed through the SDK.
- The separately pinned `2.5.4.0` experimentalF runtime was unavailable. Language generation, text tools, OCR and image descriptions correctly returned `runtimeRequired`. App Content Search and Lumen registration returned `identityRequired`; Aion returned `unsupported` because this process is x64. ODR was unavailable. The passive App Actions catalogue probe did not answer within its bounded window and returned unavailable.
- Every privileged permission remained false during the passive probe. No model, provider, framework, certificate, optional identity or microphone session was installed or activated by verification. Live inference, index preparation/rebuild/delete and installed-agent invocation/registration remain conditional acceptance lanes for a suitably configured supported machine.

Material review fixes covered early cancellation before helper assignment, cancel-control ordering, fresh consent at dispatch, independent answer/text-tool permission, transient helper session ownership, scoped registration removal verification after opt-out, persistent index statistics, semantic capability preparation, framework dependency verification, and short activation duplicate suppression. Native context/citations and image reads continue to enforce Lumen's selected-root boundaries. Frontend IPC payloads and native helper envelopes are validated.

The first configured native build exhausted disk while copying generated resources. Only this checkout's verified generated debug cache was removed. The successful rerun used `CARGO_INCREMENTAL=0`, `CARGO_PROFILE_DEV_DEBUG=0` and `CARGO_PROFILE_TEST_DEBUG=0`, without changing tracked release settings or bypassing resources.

An initial packaged startup smoke exposed a custom-manifest regression before Rust entry. Preserving Tauri's Common Controls v6 dependency restored startup in an otherwise identical test executable. The source manifest and identity validation now retain that dependency; the rebuilt installer passed the installed smoke. Fixed allowlisted checkpoints diagnose future isolated smoke failures without logging user content. A subsequent report-writing failure from mixed PowerShell module paths was resolved by importing the system Utility/Security modules explicitly and rerunning the full smoke.

The Engineering Preview SDK terms constrain production use and redistribution. Applicable terms and provenance are retained in [the helper's notices](../../workers/windows-ai/THIRD_PARTY.md); these local preview builds are not a claim that production distribution has been cleared.
